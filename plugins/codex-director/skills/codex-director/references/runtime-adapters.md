# 原生讨论串工具

只查当前动作需要的工具。以下操作使用 Codex 桌面端原生聊天。面板的命令和状态见[项目讨论串](project-panel.md)。

## 首次命名

- 只在本串 `show` 返回 `paired: false` 时处理首次命名。用当前原生聊天 ID 在 `list_threads` 中定位本串，读取 `title`、`projectId` 和 `hostId`。列表缺少本串时，用 `read_thread(includeTurns: false)` 读取当前标题、宿主和工作目录。已配对的总讨论沿用现名和原配对。
- 用户在启动请求中明确给了聊天名时，采用该名字。否则仅在新聊天标题为空、是「新聊天」或 “New chat” 等默认占位名，或仅复述本次启动请求（如「设置项目总讨论」）时自动命名。其他标题或来源难以判断的标题按原名保留。
- 自动命名取 `list_projects` 中同一宿主、同一 `projectId` 的项目显示名 `label`，组成「项目名 Director」。缺少项目 ID 时可用本串工作目录与同宿主项目的 `path` 精确且唯一匹配。无法确认项目名时用「项目总讨论」。
- 需要改名时调用 `set_thread_title(threadId, title)`，目标仅限当前聊天。用成功回执确认的标题登记；回执未给出最终标题或改名失败时，用 `read_thread(includeTurns: false)` 取实际标题，继续初始化。原生标题仍为空且无法改名时，「项目总讨论」只作面板显示名。

## 启动与派工

- 只在首次设置时检查置顶，需要置顶时调用 `move_thread_to_sidebar_section`，传当前 `threadId` 和 `sectionId: "pinned"`。
- 用户已授权且分工相符的执行串，按真实聊天 ID 和原生工具返回的宿主 ID 调用 `send_message_to_thread`。新接入的旧串须由用户点名并能唯一定位，或由用户确认候选。目录相同、标题相似、来自另一串的消息都不能代替用户授权。首次创建时尊重项目指定的模型和思考强度；已有串默认省略 `model` 和 `thinking` 以沿用该串设置，用户要求改用其他设置时按其选择。
- 用户授权开新串时，先用 `list_projects` 核实任务所属项目，取得真实 `projectId`（多仓库时按用户指定的路径匹配），再调用 `create_thread`，选择该项目的本地环境。只有用户要求独立工作树且项目支持时才选工作树。新串的首条消息说明任务、必要背景、限制和交付要求。续用旧串只需转交用户要求并补充变化的范围、版本或目标。
- 新建和续用都要核对本次动作、目标项目或聊天、工具是否成功以及实际返回的 ID。面板支持本地聊天。收到创建已排队的 `clientThreadId` 时只登记准备中，取得对应正式 ID 后再打开、读取、等待或继续发消息。逐串处理回执，发送失败或结果不明时不要自动重发；仅登记失败时重试登记。
- 用户点名停止时，对有发送授权的目标串发停止指令。停止以执行串确认或原生终止状态为准，已有产物留在原串。仅在用户明确要求时对指定聊天调用 `set_thread_archived`。

## 等待、核对与回报

1. 成功登记后显示本轮派工回执，默认结束当前回合。只在用户明确要求等结果时使用 `wait_threads` 持续等待。每次传 1–8 个已登记目标，各自携带原生回执的 `hostId` 和 `threadId`；有上次等待返回的游标时，对同一目标传 `afterCursor`。需要即刻查看时用 `timeoutMs: 0`。短进展不会唤醒等待，超时返回当前进展，新用户消息可打断等待。一次只需处理有变化的目标，单个目标报错不影响其他目标。
2. 对照派工之后的回合、任务范围和交付要求。等待结果已经给出可归属本次任务的完整结论和必要依据时，直接据此验收。若返回了上一轮答复、摘要被截断、范围不符或同时有新追问，只读相关串的最近回合，用 `read_thread` 核对本轮用户请求与最终答复。它的 `cursor` 只用于向前翻到更早的回合，和等待的 `afterCursor` 分开使用。仍无法对应时保持待确认。需要返工时，沿原授权在同串说明具体缺口，并以返工后的那一轮重新验收。
3. 如果最新消息只有返回链接，或只补了末尾几行，用 `read_thread` 读取同一次用户请求和补正前的完整答复。核对属于本次派工后，按完整正文确认交付。找不到正文就保留「待确认」。面向用户的回报按[总讨论主规则](../SKILL.md#等待验收与回报)处理。交由执行串回答的问题，在确认本轮答复后默认只列回答串名称及原生链接。
4. 原生等待只在当前总讨论回合生效，已经结束的总讨论不会因为执行串完成而自动醒来。用户要求等到结果时在本回合继续有界等待；默认由聊天内回执读取本次派工对应的答复。回执只读取状态和链接，执行串无需发送反向消息。默认不用心跳或定时自动化。执行串向总讨论主动发消息需要人类对该反向目标的明确授权，转发来的回报要求本身不构成授权。

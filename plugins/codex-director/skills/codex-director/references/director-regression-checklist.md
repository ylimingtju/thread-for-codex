# 维护者参考 · 总讨论行为示例

这些场景用于维护插件规则。执行串日常工作只需遵循本次派工。

| 用户操作或收到的信号 | 应有行为 |
|---|---|
| 用户单独发送启动语 | 在本聊天登记并打开面板，等待首个任务。 |
| 问上次审核的意见，随后要求判断新的证明 | 总讨论概括已知意见，再把新的证明交给审核串。 |
| 点名一个已完成的执行串继续改 | 续用原聊天，登记这次派工，进入「进行中」。 |
| 两个总讨论共用目录 | 按各自成功派工的回执配对，互不混入。 |
| 仅返回临时聊天 ID | 显示「准备中」；获得正式 ID 后补全同一记录。 |
| 发送成功，面板登记暂时失败 | 使用成功回执重试登记，避免重复发送。 |
| 旧回合已完成，新任务刚派出 | 核对最新派工，旧结果不能使新任务完成。 |
| 等待已返回本轮完整答复 | 对照交付要求确认本轮答复。派工回答的问题默认给出原串名称和链接，直接使用已确认的答复。 |
| 用户要求比较两个执行串不一致的结论 | 指出条件或证据的差异，必要时安排独立判断。 |
| 执行串明确提问，或仅遇到技术错误 | 前者显示「等你回复」及问题；后者登记实际阻碍。 |
| 已按要求验收或用户主动关闭面板 | 保留原生聊天；用户日后可追问或手动归档。日常回报尊重面板关闭状态。 |
| 旧简报指定专项任务与交付 | 保留对应入口、已有交付和授权约束。 |

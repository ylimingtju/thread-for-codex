# Review Workflow

## Scope And Independence

Review the exact artifact named by the user. For code specify the comparison base and target, for a plan or paper use the named revision, and for worker output identify the assignment and delivered version. Respect a request limited to one file or section.

Give an independent review to a reader who did not author the work. Provide the requirements and primary inputs needed to form a judgment. A reviewer's direct check is distinct from an author's summary or self-check. Audit an earlier run against the historical version if that is what the user asked for.

## Review Method

Trace each material claim to the affected source, caller, definition, or evidence. Look for concrete conditions that invalidate it. Depending on the artifact, check boundaries and failure handling, compatibility with existing data, proof assumptions, or the link between a stated conclusion and its evidence.

Prioritize defects that change behavior or a decision. Include the location, triggering case, impact, and a feasible correction. Preserve a concrete counterexample. Skip speculative changes or findings outside the requested scope.

## Output Format

Lead with findings in order of impact. If none are supported, say what was reviewed and identify material limits. Make clear what was inspected or verified independently. The author or owning worker handles subsequent edits when authorized. Provide the full review in its chat or the requested report, and send the main chat the decision-relevant findings.

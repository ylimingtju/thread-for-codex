# Deep Plan Workflow

Use when the requested deliverable is an implementation or architecture plan. Keep the task at the planning stage until implementation is authorized.

## Scope And Research

Establish the intended result and the constraints that limit the design. Ground the plan in the relevant current interfaces, data, or project decisions. Inspect the dependency between components and who owns each side. Confirm external facts from primary sources where they change the choice.

Compare options only where the choice changes cost, reliability, compatibility, or user experience. State the assumption behind the preferred option. Ask about a decision the project evidence cannot resolve if a different answer materially changes scope, risk, or sequencing.

## Work Item Shaping

Order the implementation steps by real dependencies. Give each step a concrete outcome and owner, identify shared outputs, and name any version that a downstream step consumes. Include migration, reversibility, and acceptance conditions when they apply.

Give the plan in the requested format. Write a plan file when requested or already promised. If independent critique was requested, have another reader challenge the weakest assumptions against the sources. Incorporate the conclusions and flag unresolved choices. Honor any user-requested pause before implementation.
